¿Cómo deben ser los archivos?

Para poder ser leídos por la web app, los archivos deben tener una estructura concreta.

Estos requisitos se han definido siguendo las carácterísticas más comunes de los archivos de datos abiertos.

En primer lugar, deben tener los datos de latitud y longitud en dos columnas separadas.

Para que la web app localize de manera automática las coordenadas, el nombre de los campos de las coordenadas deben ser los siguientes:
(también serían válidos en mayúsculas o con mayúsculas y minúsculas mezcladas)

Nombres para el campo de la latitud:

  • - lat
  • - lati
  • - latitude
  • - latitud
  • - y
  • - latitud_y
  • - lat-x, lat_y


Nombres para el campo de la longitud:

  • - lon
  • - lng
  • - long
  • - longitude
  • - longitud
  • - x
  • - longitud_x
  • - lon-y, lon_x, lng_x

Si no coinciden exactamente, la app busca una única columna que contenga «lat» y otra que contenga «lon» o «lng», con valores dentro de rango. Si aun así no las encuentra, te pedirá que elijas las columnas de las coordenadas al subir el archivo.

Las filas sin coordenadas, o con 0,0, no se dibujan; la app te dice cuántas hay.


Archivos CSV

El único requisito para poder utilizar un archivo CSV es que el archivo cuente con cabecera. El separador puede ser coma, punto y coma, tabulador o barra vertical, y los decimales pueden llevar punto o coma.

Como se puede ver, la línea número uno es la cabecera, que da nombre a los valores de las líneas siguientes.

Además, como los campos de las coordenas cumplen con los nombres mencionados anteriormente (Lat y Lon), por lo que la web app será capaz de encontrar las coordenas de manera automática, y cumple también con el requisitos de tener las coordenadas en campos distintos.


Archivos JSON y GeoJSON

El archivo JSON debe ser una lista de objetos (o un objeto que contenga esa lista). Si un objeto tiene otro dentro, sus campos se convierten en columnas con nombres como «direccion.calle».

También se aceptan archivos GeoJSON con puntos: la app crea las columnas «latitud» y «longitud».

Como se puede ver, cada ítem está limitado por llaves ( { ... } ) y está separado por comas ( {...} , {...}) del anterior y del siguiente item.

Además, como los campos de las coordenas cumplen con los nombres mencionados anteriormente (lat y lon), por lo que la web app será capaz de encontrar las coordenas de manera automática, y cumple también con el requisitos de tener las coordenadas en campos distintos.
